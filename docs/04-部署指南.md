# 部署指南

项目采用 **Docker Compose** 编排，共 4 个容器：MySQL、Redis、Backend（Spring Boot）、Frontend（Nginx 反代 + 静态资源）。支持**联机构建部署**和**离线镜像包部署**两种方式。

## 1. 容器架构

| 服务 | 镜像 | 容器名 | 宿主端口 | 对外暴露 |
|------|------|--------|---------|---------|
| mysql | mysql:8.0 | takeaway-mysql | 无 | 否（仅容器内网）|
| redis | redis:alpine | takeaway-redis | 无 | 否 |
| backend | takeaway-backend:v1 | takeaway-backend | 8081 → 8080 | 否 |
| frontend | takeaway-frontend:v1 | takeaway-frontend | 8091 → 80 | **是（唯一入口）** |

- 前端 Nginx 反代 `/api`、`/uploads`、`/ws` 到 backend，并对 `/ws` 做 WebSocket Upgrade。
- 对外**仅暴露 8091**，后端和数据库均不直接暴露，提高安全性。

## 2. 方式一：本地联机构建部署

### 前置
- Docker / Docker Compose
- 国内镜像源（如需）：基础镜像可改用 `docker.1panel.live` 等国内源（本项目相关 Dockerfile/compose 已配置）
- Maven、Node.js（用于本地构建产物）

### 构建

```bash
# 1. 构建后端 jar
mvn clean package -DskipTests

# 2. 构建前端产物
cd frontend
npm install
npm run build:prod
cd ..

# 3. 构建 Docker 镜像
docker build -t takeaway-backend:v1 -f Dockerfile .
docker build -t takeaway-frontend:v1 -f frontend/Dockerfile frontend
```

### 启动

```bash
# 准备好数据库脚本 + 上传目录
mkdir -p uploads        # 后端挂载点，需手动创建避免权限问题

# 启动全部服务
docker compose up -d

# 查看状态
docker compose ps
```

启动成功后访问 `http://localhost:8091`。

> 首次启动时，`sql/00_complete_init.sql` 会自动导入 MySQL（容器首次初始化执行）。

### 停止 / 清理

```bash
docker compose down          # 停止容器
docker compose down -v       # 停止并删除卷（数据清空，慎用）
```

## 3. 方式二：离线镜像包部署（服务器无外网）

### 本机导出
```bash
# 导出 4 个镜像为一个 tar 包
docker save -o takeaway-images.tar \
  takeaway-backend:v1 \
  takeaway-frontend:v1 \
  mysql:8.0 \
  redis:alpine

# 可选：压缩以便传输
gzip takeaway-images.tar
```

### 需上传的文件
```
/opt/bzy-takeaway/
├── takeaway-images.tar        # 镜像包（约 430 MB 或压缩后更小）
├── docker-compose.yml          # 编排文件
└── sql/
    └── 00_complete_init.sql    # 数据库初始化
```

### 服务器部署
```bash
cd /opt/bzy-takeaway
mkdir -p uploads                # 手动创建上传目录，避免权限问题
docker load -i takeaway-images.tar   # 载入镜像
docker compose up -d            # 启动
```

### 端口与安全组
- 对外端口 8091 需在**服务器安全组**中放行。
- 若需绑定域名，配置 DNS 记录后，在 Nginx 或云服务器反代 8091。

## 4. Nginx 配置要点

`frontend/nginx.conf`（前端镜像内）核心片段：

```nginx
# /api 与 /uploads 反代到后端
location /api/     { proxy_pass http://backend:8080; proxy_set_header Host $host; ... }
location /uploads/ { proxy_pass http://backend:8080; proxy_set_header Host $host; ... }

# /ws WebSocket 升级
location /ws {
    proxy_pass http://backend:8080;
    proxy_http_version 1.1;
    proxy_set_header Upgrade $http_upgrade;
    proxy_set_header Connection "upgrade";
    proxy_read_timeout 3600s;
    proxy_send_timeout 3600s;
}
```

- 前后端通过**相对路径 `/api`** 通信，本地与服务器共用同一份前端构建，无需硬编码地址。
- WebSocket 地址由前端基于当前 `location.host` 动态生成。

## 5. 配置说明

- 数据库/Redis 密码等敏感项通过 `docker-compose.yml` 的 `environment` 注入，支持 `.env` 文件覆盖（未提供 `.env` 时使用 compose 默认值）。
- 后端生产配置见 `src/main/resources/application-prod.yml`，通过 `SPRING_PROFILES_ACTIVE=prod` 激活。
- 图片上传目录为宿主 `./uploads`，挂载到容器 `/app/uploads`。

## 6. 生产环境注意

- 生产环境请**务必修改默认数据库/Redis 密码**（通过 `.env` 覆盖）。
- 支付宝回调地址（`http://<域名>:8091/#/pay-result`）需配置为公网可访问地址。
- 建议配合 HTTPS 使用（Nginx 配置证书）。
