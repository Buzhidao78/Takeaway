# 数据库设计

数据库名 `bzy_takeaway`，使用 `utf8mb4` 字符集，共 **26 张表**，覆盖用户、商家、菜品、订单、支付、配送、评价、通知、收益等业务。

数据库初始化脚本见 [sql/00_complete_init.sql](../sql/00_complete_init.sql)，含建表 + 种子数据 + 完整测试数据。

## 2. 用户与角色

### sys_user（系统用户）

四种角色的统一账号表，通过 `role` 字段区分：

| 字段 | 类型 | 说明 |
|------|------|------|
| id | bigint | 主键 |
| phone | varchar(20) | 手机号（登录账号，唯一）|
| password | varchar(100) | BCrypt 加密密码 |
| nickname | varchar(50) | 昵称 |
| avatar | varchar(255) | 头像 |
| role | tinyint | 0用户 1商家 2骑手 3管理员 |
| status | tinyint | 账号状态 |

> 登录流程：手机号 + 密码 → JWT 签发（含 userId、phone、role）→ `AuthInterceptor` 按角色做接口鉴权。

### 认证/地址/短信
- `user_address`：收货地址（收货人、电话、详细地址、经纬度、是否默认）。
- `sms_log`：短信验证码发送与校验记录（Redis 同时存储验证码）。

## 3. 店铺与菜品

```
store（店铺） 1 ── n store_category_rel（店铺-分类关联）n ── 1 global_category（全局分类）
        │ 1
        └── n category（店内菜品分类）1 ── n dish（菜品）
```

- `store`：店铺信息（logo、banner、评分、营业状态、审核状态、经纬度）。
- `global_category`：全局分类（如快餐、甜品等），用于首页分类导航。
- `store_category_rel`：店铺挂载到哪些全局分类。
- `category`：店铺内部餐饮分类（如主食、饮品）。
- `dish`：菜品（名称、价格、图片、销量、上下架、分类归属）。

## 4. 购物车与订单

### 订单状态机

```
┌────────┐  支付成功   ┌────────┐   商家接单   ┌────────┐   出餐   ┌────────┐   完成   ┌────────┐
│ 0 待支付 │ ──────────▶ │ 1 已支付 │ ──────────▶ │ 2 制作中 │ ──────▶ │ 3 配送中 │ ─────▶ │ 4 已完成 │
└────────┘             └────────┘             └────────┘         └────────┘          └────────┘
    │ 取消/超时                                                        │
    ▼                                                                 ▼
┌────────┐                                                      ┌────────┐
│ 5 已取消 │                                                      │ 5 已退款 │
└────────┘                                                      └────────┘
```

### 核心表

| 表 | 职责 |
|----|------|
| `orders` | 订单主表：金额（商品/包装/配送/支付）、状态、支付方式与时间、流水号 |
| `order_item` | 订单明细：**保存下单时菜品名称/价格快照**，保证历史订单不随菜品变更 |
| `order_status_log` | 状态流转日志：完整记录每一次状态变更（审计）|
| `cart` | 购物车：用户与店铺维度的菜品预选清单 |

> 订单金额采用 `decimal(10,2)`，通过 `goods_amount + packaging_fee + delivery_fee - discount_amount = pay_amount` 勾稽校验，保证账目严谨。

## 5. 配送与骑手

```
delivery_zone（配送区域规划）          merchant_delivery_config（商家配送配置）
rider（骑手）1 ── n delivery_order（配送单）
rider_online（在线状态）    rider_location（实时位置）    rider_earnings（收益流水）
```

- `delivery_order`：配送单，记录订单配送状态、指派骑手、配送完成时间。
- `delivery_zone`：配送区域（用于计算是否可配送 / 配送费）。
- `merchant_delivery_config`：商家配送设置（起步价、每公里费用、免配送费门槛等）。
- `rider`：骑手资料与认证信息。
- `rider_audit_history`：管理员审核骑手的每次记录。
- `rider_online` / `rider_location`：骑手在线与实时位置（支撑抢单与派单）。
- `rider_earnings`：骑手每单收益流水。

## 6. 评价与通知

- `review`：店铺评价（评分 1-5、内容、商家回复、审核状态）。
- `product_review`：菜品评价，支持**追评、点赞/点踩、商家回复**。
- `review_vote`：评价投票记录，防止重复点赞/点踩。
- `notification`：通知消息（先持久化，再实时推送，保证可靠性）。

## 7. 收益体系

- `store_earnings`：商家收益流水。
- `rider_earnings`：骑手收益流水。

两套收益表独立记录，支持商家端与骑手端的收益统计与明细查看。

## 8. 通用设计约定

- **逻辑删除**：所有业务表含 `deleted` 字段，配合 MyBatis-Plus 逻辑删除，不物理删除数据。
- **时间字段**：统一 `create_time` / `update_time`，`update_time` 使用 `ON UPDATE CURRENT_TIMESTAMP` 自动刷新。
- **索引**：外键关联字段（`user_id`、`store_id`、`order_id`、`dish_id`）均建索引，订单号建唯一索引。
- **金额**：统一 `decimal(10,2)`，杜绝浮点误差。
