# 功能模块划分

按**四大角色**组织功能，从「功能点 → 后端 Controller → 前端页面」三层对照。后端以 `src/main/java/com/bzy/takeaway/controller/` 的 17 个 Controller 为核心，前端页面统一在 `frontend/src/views/` 下按角色分目录。

## 0. 总览

| 模块 | 后端 Controller | 前端 views |
|------|----------------|-----------|
| 用户端 | Auth、Store、GlobalCategory、Banner、Cart、Order、Pay、Review、Notification、UserAddress、File | 根目录 `views/*.vue` |
| 商家端 | Merchant、DeliveryConfig、ProductReview | `views/merchant/` |
| 骑手端 | Rider | `views/rider/` |
| 管理端 | Admin、AdminRider | `views/admin/` |

---

- **WebSocket**：`RiderWebSocketHandler` 向后端推送新订单 → `useRiderWebSocket.js` 前端实时接收。
- **Redis 分布式锁**：防止多个骑手同时抢到同一订单（`GrabOrderService`）。

## 5. 后端包结构对照

业务逻辑按模块分散在 `service/`（接口）与 `service/impl/`（实现），与 Controller 一一对应：

```
service/
├── AuthService / AuthServiceImpl
├── StoreService / StoreServiceImpl
├── CartService / CartServiceImpl
├── OrderService / OrderServiceImpl
├── PayService（支付宝）
├── RiderService / RiderServiceImpl
├── GrabOrderService / GrabOrderServiceImpl（抢单）
├── MerchantService / MerchantServiceImpl
├── AdminService
├── AdminRiderService
├── NotificationService / NotificationServiceImpl
├── ReviewService / ReviewServiceImpl
├── ProductReviewService / ProductReviewServiceImpl
├── UserAddressService / UserAddressServiceImpl
├── DeliveryConfigService / DeliveryConfigServiceImpl
├── DeliveryFeeService（配送费计算）
├── GlobalCategoryService / GlobalCategoryServiceImpl
├── SmsService / SmsServiceImpl（短信验证码）
└── FileService（文件上传）
```

每个 Service 均为**面向接口编程**：接口保留原类名（如 `OrderService`），实现在 `service/impl/OrderServiceImpl`，保证 Controller 依赖注入无需改动。
